# docs-sync-audit

## Why

The 2026-09-01 geometry audit closed with a six-item remediation plan; P1–P5 have all landed and
been archived. P6 is the final item: a batch of documentation and spec defects (D1–D8; D9 was
resolved by `unify-shape-reflection-policy`) that make the repo's own description of itself wrong —
including two README examples that raise on execution, a CLAUDE.md line contradicting the shipped
shape estimator, matched-seed docstrings claiming more than the machinery delivers, and two
contradictory statements of SNF's production status. One of the eight (D8) is a latent code hazard:
stage levels sort as strings, so stage ordering silently breaks at `n_stages ≥ 10` ("10" < "2"),
and path length and shape both depend on stage order.

## What Changes

- **D1** — `CLAUDE.md` trajectory line: "iterative Procrustes GPA" → strict pairwise ordinary
  Procrustes alignment over all orthogonal transforms (reflections aligned away), matching
  `_estimate_shape` and the shape spec since `unify-shape-reflection-policy`.
- **D2** — `README.md` `motco simulate` example: drop the nonexistent `--prop-affected-features`
  flag and the "requires R + InterSIM" comment; the example must run against the numpy generator
  CLI as shipped.
- **D3** — `README.md` Python example: rewrite against the real API
  (`SemiSyntheticTrajectoryParams` + `generate_semisynthetic_trajectory`);
  `generate_semisynthetic_trajectory_from_intersim`, `InterSIMParams`, and
  `prop_affected_features` no longer exist.
- **D4** — `docs/roadmap.md`: move the resolved shape-invariance bullet from "Not yet established"
  to "Established".
- **D5** — `openspec/specs/semisynthetic-trajectory-generator/spec.md` purpose line: datasets are
  generated by the numpy generator from the cached InterSIM reference, not "from InterSIM outputs".
  (Purpose-line wording only; no requirement changes, edited directly rather than via a delta.)
- **D6** — Narrow the matched-seed claims to what actually matches: `grid.py`
  (`derive_replicate_seed` docstring: family cells do **not** generate "the *same* dataset"),
  `showcase.py` (`the only thing that changes is group B's transform` overstates), and the
  pivotality diagnostic config note ("same generator draws"). Only the baseline indicator draw and
  group assignment are shared; the transforms consume different RNG amounts, so sampled values
  differ across modes — the sole common-random-numbers pair is `none`↔`magnitude`.
- **D7** — One consistent SNF status message. The roadmap's evidence-backed position wins (SNF's
  graph-spectral geometry is not aligned with the Euclidean trajectory statistics; deferred pending
  graph-native statistics): `CLAUDE.md` and the `evaluation.py` module docstring stop calling SNF a
  "production latent-space method" and adopt the roadmap's framing (PLS is the production
  measurement space; SNF remains a supported integration path).
- **D10** (found during implementation, same defect class as D2) —
  `openspec/specs/toy-dataset/spec.md` publishes a "canonical regeneration command" that passes the
  nonexistent `--prop-affected-features` flag, and claims the committed fixture is what
  `motco simulate` produces. The fixture actually predates the numpy generator (its `truth.json`
  carries `intersim_metadata` and no `n_stages`/`p_dmp`/`baseline_continuity`), so the current CLI
  cannot reproduce it. The spec is corrected to describe the fixture as pinned, with the
  current-CLI equivalent marked as a distinct dataset rather than a reproduction.
- **D8** (the one code change) — Numeric-aware level ordering: when every level label of a factor
  parses as an integer, order levels numerically; otherwise keep lexicographic order. Applied
  consistently in `stats/design.py` (`get_model_matrix`) and
  `simulations/evaluation.py` (`build_simulation_trajectory_design`), byte-identical for every
  existing configuration (all current stage labels are single digits), plus a regression test at
  `n_stages ≥ 10`.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `simulation-evaluation-harness`: the design-objects requirement gains a level-ordering contract —
  stage and group levels whose labels are all integer-like are ordered numerically, so stage order
  is correct at `n_stages ≥ 10`; non-numeric label sets keep deterministic lexicographic order.
- `toy-dataset` (D10): the fixture is specified as pinned and provenance-recorded rather than
  regenerable by the current CLI; the published command must be one the shipped parser accepts.

## Impact

- **Code**: `src/motco/stats/design.py` (shared level-sort helper + `get_model_matrix`),
  `src/motco/simulations/evaluation.py` (`build_simulation_trajectory_design`),
  `src/motco/simulations/grid.py` and `showcase.py` (docstrings only).
- **Docs**: `CLAUDE.md`, `README.md`, `docs/roadmap.md`,
  `openspec/specs/semisynthetic-trajectory-generator/spec.md` (purpose line),
  `examples/trajectory_power_study/angle_pivotality_diagnostic.json` (notes array).
- **Tests**: new ordering regression test (design + harness at ≥ 10 stages); existing suites must
  pass unchanged — D8 is byte-identical for all label sets currently in use (single-digit stages,
  string group labels `A`/`B`).
- **Compatibility**: no statistic, schema, or signature changes; no effect on committed study
  records or resume signatures. Ordering changes only for factors with integer-like labels ≥ 10,
  which no existing config uses.
