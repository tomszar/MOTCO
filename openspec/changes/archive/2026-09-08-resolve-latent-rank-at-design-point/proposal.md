# resolve-latent-rank-at-design-point

## Why

Phase 5 readiness item 3 ([`docs/phase5-readiness.md`](../../../docs/phase5-readiness.md) §3, "Reconsider latent dimensionality for group contrasts") is the last open scientific item before the paper-grade study, and it decides the integration configuration Phase 5 commits to. The planned Phase 5 baseline currently reads "pooled PLS … with CV-selected rank" by inheritance, not by evidence: stage-supervised double CV saturates at `n_stages − 1 = 3` at the chosen design point for every n ([design-point report](../../../docs/reports/phase5-design-point-pilot-2026-09-08.md), "PLS representation"), a rank-3 space retains only ~6% of the observed orientation contrast, and the one measurement that varied rank — the [latent-rank probe](../../../results/latent-rank-probe-2026-09-03/latent_rank_probe.md) — ran at the *old* design point (n = 300, `p_dmp = 0.2`, clamped surgery) and measured only `shape`. Whether a larger retained rank buys orientation `angle` power, costs magnitude or shape power, or moves Type I error at ρ = 0, n = 1200, `p_dmp = 0.1` has never been measured. The study harness cannot measure it today either: `design_grid` and `axes` address only top-level `generator.`/`evaluation.` fields, and the rank override lives inside `evaluation.integration_params`.

The geometry audit's caution binds the answer: any group-aware sizing puts group information into the measurement space and voids the fixed-latent-space RRPP conditioning. So the candidates are only rules statable without group labels — the existing stage-supervised CV, or a predeclared fixed rank — and the decision must be made from a matched comparison at the design point Phase 5 will actually run.

## What Changes

- **Nested evaluation axes.** `axes` and `design_grid.axes` accept dotted paths into the evaluation integration-parameter mapping — concretely `evaluation.integration_params.forced_components` — in addition to top-level fields. JSON `null` is a legal axis value meaning "key absent", so the baseline column for the rank axis is the CV-selected configuration and every other column is a forced rank. The nested value enters the cell's evaluation parameters (and therefore the parameter signature and the design-point coordinates) exactly as a top-level axis does. Configs that use no nested axis enumerate and report unchanged.
- **Same data, different measurement.** Design-point columns that differ only in an evaluation-namespace coordinate share the primary matched-seed family *and* the generated datasets by design (the duplicate-dataset guard already keys on evaluation identity); the report states this pairing explicitly so rank columns are read as one dataset measured at several ranks, not as independent draws.
- **Rank-ladder reporting.** `design_point_operating.csv` (already resolved per design point with rejection rate, MC SE, eigengap, `angle` null-width dispersion, and selected-LV distribution) gains the component-selection mode (`cv`/`forced`) per row, and the report adds a rank-ladder figure (per mode, each statistic's rejection rate against retained rank, MC error bars) when the rank axis is declared.
- **Predeclared, advisory rank decision.** A new `acceptance.rank_decision` block names the baseline column (CV), the target pair (orientation / `angle`), the protected pairs (magnitude / `delta`, shape / `shape`), the null tolerance, and the SE multipliers. The report evaluates it against the baseline column: a fixed rank *qualifies* when it (a) raises the target power at the top effect by more than the declared multiple of the pooled MC SE, (b) keeps every statistic's zero-effect anchor within the Type I bound, and (c) does not lower either protected power at the top effect by more than the declared multiple of SE. Verdict: `keep_cv` when no rank qualifies, otherwise `adopt_fixed_rank` naming the smallest qualifying rank (parsimony predeclared). Output `rank_decision.json` + CSV; it never feeds the Phase 4 gate or the acceptance targets.
- **Ladder profile** `examples/trajectory_power_study/phase5_latent_rank_ladder.json`: the chosen design point held fixed (ρ = 0, n = 1200, four stages, `p_dmp = 0.1`, default fail-loud censoring, effects 0 / 0.25 / 0.50 / 1.00), **all four modes** (magnitude, orientation, shape, translation), design axis `forced_components ∈ {null, 3, 4, 6, 9, 12}`, 100 replicates × 199 permutations, matched seeds with one shared zero-effect anchor per column, attribution off, gate off. Forced 3 is included so CV-selection variability (recorded range 2–4) is separated from the rank itself, and because "fixed `n_stages − 1`" is itself a candidate group-blind rule. The CV column doubles as the re-measurement of magnitude and shape at the chosen point that the design-point report says Phase 5 must do.
- **Run the ladder and record the decision.** Committed `report/` outputs and `PROVENANCE.txt` under `results/phase5-latent-rank-<run date>/`; a dated findings report under `docs/reports/`; `docs/phase5-readiness.md` item 3 resolved with the committed rank rule; `docs/roadmap.md` Phase 5 planned baseline names that rule and the "Not yet established" list is updated; study READMEs document the nested-axis syntax and the rank rule; `CLAUDE.md` study bullet updated.

Out of scope: a new group-aware component-selection criterion (cautioned against by the audit); any change to the `angle`, `delta`, or `shape` statistics or the RRPP test; the surgery transforms; generalizing axes to arbitrary nested paths beyond the evaluation integration-parameter mapping; the 500-replicate Phase 5 grid itself.

## Capabilities

### New Capabilities

(none)

### Modified Capabilities

- `simulation-grid-orchestration`: parameter axes may address nested evaluation integration parameters (dotted path, `null` meaning absent), applied into the evaluation parameters so they enter the parameter signature; top-level axis behavior is unchanged.
- `trajectory-power-study`: the declarative configuration accepts nested evaluation axes in `axes` and `design_grid` with the baseline-value rule applied to the nested value; evaluation-only design columns are declared to share datasets; the design-point operating table carries the component-selection mode and the report renders a rank-ladder figure; a predeclared, advisory rank decision rule is evaluated against the baseline column; the study provides a fixed Phase 5 latent-rank ladder profile with a versioned findings report and the readiness worklist records the committed rank rule.

## Impact

- `src/motco/simulations/grid.py` — `_split_axis` / `_apply_axis_value` / `_get_axis_value` learn the nested `evaluation.integration_params.<key>` form; `replace(evaluation_params, integration_params={...})` with `None` deleting the key.
- `src/motco/simulations/study/config.py` — `_validate_axis_namespace` and `axis_baseline_value` accept the nested form and resolve the baseline from the mapping (absent → `None`); `null` axis values survive `dump_study_config` round-trip; new `RankDecisionRule` under `AcceptanceTargets.rank_decision` with validation (baseline value present in the rank axis, target/protected modes in `trajectory_modes`, non-negative multipliers).
- `src/motco/simulations/study/enumerate.py` — no enumeration-policy change expected; design points already carry every axis in metadata and the duplicate-dataset guard already includes evaluation identity. Verify only.
- `src/motco/simulations/study/spectrum.py` — `component_selection` column in the design-point operating frame.
- `src/motco/simulations/study/targets.py`, `report.py` — `evaluate_rank_decision` / `write_rank_decision`; rank-ladder figure; both written only when the rank axis is present.
- `examples/trajectory_power_study/` — new ladder config and README section; `src/motco/simulations/study/README.md` configuration table and outputs tree.
- Tests — nested-axis parsing and rejection cases, baseline resolution with `null`, signature differs per rank column, ladder profile enumerates (cell count, no headroom rejection, every column shares seeds and datasets with the baseline), decision rule cases (`keep_cv`, `adopt_fixed_rank`, protected-power veto, anchor veto), report writes the new files only for a rank-axis study, existing fixtures re-report byte-identically.
- Docs — `docs/phase5-readiness.md` item 3, `docs/roadmap.md` (Phase 5 planned baseline, "Not yet established", "Next three changes"), `CLAUDE.md`, the dated findings report.
- Compatibility — no generator or evaluation-field changes; existing configs, shards, and committed results resume and re-report unchanged. Forced-rank cells have a different evaluation identity and signature from CV cells by construction.
